## Auth in the browser

- **No tokens in the browser.** Login is a plain link to `/auth/login`, which the Vite proxy forwards to the server. The server finishes the OIDC flow, sets an httpOnly cookie and redirects back to `WEB_ORIGIN`.
- **Session check.** On load the app calls `/api/me`. A 401 shows the login screen, and a 200 stores the user and their workspaces in an `AuthProvider`.
- **Every fetch sends the cookie.** A 401 anywhere drops the app back to the login screen.
- **Roles.** Admin-only buttons (release someone else's claim) render only for admins. The server enforces the rule anyway.
- **Contractor case.** Eli belongs to two workspaces, so he gets a workspace switcher. Each workspace has its own socket and its own data.

## Real time without losing frames

- **The `useFeed(workspace)` hook** opens `/ws?workspace=X&after=<lastSeq>` and keeps `lastSeq` in memory.
- **Reconnect.** It reconnects with backoff and asks for `after=lastSeq`, so frames missed while the socket was down are replayed.
- **Duplicates are harmless** (**Make Operations Idempotent**). A reducer applies frames by `seq` and ignores any it has already seen. Message ids are unique within a conversation, and status only moves forward, as on the server.
- **After a reconnect** it also refetches the open conversation, which covers any gap.

## Replies

- The browser makes `client_ref` with `crypto.randomUUID()` before sending. A double click or a retry is therefore the same reply, which the server already treats as one.
- The message shows **queued** at once, then moves through sent, delivered or failed as status frames arrive.
